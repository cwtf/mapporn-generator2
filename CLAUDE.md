# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

MapPorn Generator: a browser app where an LLM agent builds r/MapPorn-style maps by calling tools. React + d3-geo front end (Vite), plus a small Express server that relays LLM calls and runs web-research tools. Node 20+.

## Commands

```bash
npm install
npm run dev        # tsx watch server (port 8787) + Vite (port 5173, proxies /api → 8787)
npm run typecheck  # tsc -b over both tsconfig.app.json (src/) and tsconfig.server.json (server/)
npm run build      # typecheck + vite build → dist/
npm start          # production: server serves dist/ and /api on one port (PORT, default 8787)
npm run geodata    # regenerate public/data from Natural Earth (downloads ~55 MB into .cache/)
```

There is no test suite or linter; `npm run typecheck` is the correctness check. `.claude/launch.json` defines the `mapgen-dev` preview (runs `npm run dev`, port 5173).

## Architecture

**Deployment:** `server/app.ts` builds the Express app; `server/index.ts` adds static serving and `listen` for `npm start`, and `api/index.ts` re-exports the app as the Vercel function (`vercel.json` rewrites `/api/*` to it; Vite output in `dist/` is served by Vercel's CDN).

**The agent loop runs in the browser, not the server.** `src/agent/agent.ts` (`runAgent`) calls the LLM, executes tool calls one at a time in order, and loops until the model stops calling tools or `maxSteps` is hit. The server is only a relay (`/api/llm/chat`, `/api/llm/models`) and a host for research tools (`/api/tools/:name`) — it exists to avoid CORS and attach provider auth headers.

**Two kinds of tools, both declared in `src/agent/tools.ts`:**
- *Map tools* (`mapTools`) have a `run` executor that mutates the zustand map store directly via `useMapStore.getState().update(draft => …)` (structured-clone copy-on-write). They return a text result for the model, including an "Unmatched" note listing region refs that failed to resolve.
- *Research tools* (`researchTools`) are schema-only on the client; `executeTool` POSTs them to `/api/tools/:name`, implemented in `server/research.ts`. Adding one means adding the schema in `tools.ts` and the implementation to the `researchTools` record in `server/research.ts`.

`TOOL_DEFS` (map + research schemas) is what gets sent to the model.

**Provider abstraction** (`src/agent/llm.ts`): the internal transcript is provider-neutral (`ChatMessage` with `Part`s: `text`, `reasoning`, `tool_call`, `tool_result` — see `src/agent/types.ts`). `llm.ts` converts to/from Anthropic Messages or OpenAI Chat Completions format, handles SSE streaming for both, and `sanitize()` patches transcripts so every tool call has a result (stopped turns get synthetic "Cancelled" results). Anthropic reasoning parts must round-trip their `signature`/`redacted` data unchanged. `server/index.ts` `endpoint()` normalizes base URLs per format.

**MapState is the single source of truth** (`src/map/types.ts`, held in `src/store/mapStore.ts`). It is plain serializable data: projection settings, per-region fills, choropleth config, labels/markers/lines, legend, style, `focus` bbox, and user pan/zoom `view`. The renderer (`src/map/MapView.tsx`) and export (`src/map/exportMap.ts`) derive everything from it. The logical canvas is fixed at `MAP_WIDTH × MAP_HEIGHT` (1600×1000); legend layout coordinates are in these units.

**Chat persistence and snapshots** (`src/store/chatStore.ts`, `src/db.ts`): chats are stored in IndexedDB. Each turn's final assistant message carries a `map` snapshot (enables "Show map from here"). Each user message is prefixed with a hidden text part from `briefMapState()` so the model notices manual edits. Manual map edits are persisted into the open chat via a debounced store subscription. Before restoring a saved map, `prepareMap` lazy-loads any subdivision geometry it references.

**Geodata and region resolution** (`src/map/geodata.ts`, singleton `geo`): loads `public/data/countries.json` (TopoJSON) up front and `public/data/admin1/<ISO3>.json` per country on demand. `resolve`/`resolveMany` map refs — ISO3, ISO2, ISO 3166-2 (`US-CA`), names/aliases (`EXTRA_ALIASES`), or group selectors (`continent:…`, `subregion:…`, `USA:*`, `all`) — to region ids. Coloring a subdivision id auto-enables that country's subdivisions (`ensureSubdivisionsShown`). `public/data` is generated by `scripts/build-geodata.mjs`; don't hand-edit it.

**Projections** (`src/map/projections.ts`): the `PROJECTIONS` registry (d3-geo, d3-geo-projection, d3-geo-polygon) tags each entry with a `group` (UI/tool-description grouping) and a `kind` that controls framing in `buildProjection`: azimuthal/conic are rotated to the focus bbox center, interrupted/polyhedral keep fixed layouts (zoom_to crops but doesn't recenter), `albersUsa` is composite. The `set_projection` tool description is generated from this registry, so new projections appear to the model automatically.

**System prompt** lives in `src/agent/prompt.ts` and encodes cartographic guidance (projection choice, palettes, always cite sources in `set_title`).

## Conventions and constraints

- Server code uses NodeNext resolution: relative imports need `.js` extensions (`./research.js`). Front-end uses bundler resolution without extensions.
- The server binds to `127.0.0.1` by default because the LLM relay forwards to user-supplied URLs. `assertAllowed` in `server/app.ts` restricts relay targets to `MAPGEN_ALLOWED_PROVIDERS`, which defaults to unrestricted locally and to the hosted provider presets on Vercel (`VERCEL` env set). Research fetches go through `safeGet` in `server/net.ts`, which rejects private/loopback addresses and caps response size. Any fetch to a URL the agent supplies must use it.
- Nominatim geocoding is rate-limited to 1 req/s (`nominatimSlot` in `server/research.ts`); research results are cached in memory for 10 minutes.
- API keys and provider profiles live in browser localStorage (`src/store/settings.ts`, zustand `persist`); the server never stores them.
